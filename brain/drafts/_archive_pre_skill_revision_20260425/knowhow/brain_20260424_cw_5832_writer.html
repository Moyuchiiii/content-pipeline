FAQ

プログラミング経験ゼロでも業務自動化案件は取れますか

取れます。わたし自身、クラウドワークスに登録した時点でプログラミング経験はほぼゼロでした。Claude Code に要件を日本語で伝えると、コードは Claude Code が書いてくれます。やることは「クライアントと要件を整理する」「出てきたコードが動くか確認する」の 2 つです。

Claude / Claude Code は有料プランが必要ですか

無料の Claude（claude.ai のブラウザ版）でも、案件分析・応募文作成まではできます。ただし実装フェーズで使う Claude Code は月 20 ドルの Pro プラン契約が実質必要です。1 件受注できれば、Pro プランの月額は十分カバーできる水準の単価が業務自動化領域の相場です。

AI 使用を明記しないと不正になりますか

クラウドワークスは「AI 使用 OK 案件」「AI 使用 NG 案件」「AI 使用可否未記載案件」の 3 種類があります。「AI 使用 NG 案件」に該当する案件に AI 生成物をそのまま納品するのは規約違反です。「AI 使用 OK」「未記載」の案件では、AI を使ったと明記する義務はありません。ただし、プロポーザルで「AI を活用して効率化します」と公言する戦略は単価アップの交渉材料になる場合があります。

非エンジニアでも業務自動化案件の納品は本当にできますか

案件の難易度による、が答えです。「Excel のマクロで売上集計を自動化して毎週メール送信」のような要件が固まった案件なら、Claude Code に指示するだけで納品物が出来上がります。一方「既存システムの API を叩いて独自ダッシュボードを構築」のような要件が流動的な案件は、最初のうちは避けたほうが無難です。記事内で受ける案件・避ける案件の判定基準を細かく書きました。

note 版との違いは何ですか

note 版は「内訳分解の事実」と「非エンジニアが選ぶべき領域はどこか」までを書いた無料記事です。Brain 版はそれに加えて、応募文テンプレ 5 パターン全文・Claude 指示プロンプト 10 本全文・実案件 3 件の全工程ケーススタディ・検索キーワード集 30 個以上・継続案件化のチェックリストを同梱した実務用マニュアルです。記事の容量は note 版の約 6 倍です。

AI 案件 5,832 件の内訳を分解する

ここから先は ¥2,980。

「AI案件」という括りを 5 つの領域に分解したときに初めて、どこに非エンジニアの参入余地があるかが見えてくる。

わたしがクラウドワークスで 8 ヶ月間、毎日検索を続けて整理した 5 領域が以下の 5 つ。

領域① AI ライティング（推定 3,000 件以上）

SEO 記事・ブログ記事・要約・リライト。この領域が検索結果の上位をほぼ独占している。単価は 1 文字 0.3〜1 円。1 記事 3,000 字書いても 900 円〜3,000 円。競合は桁違いに多い。ChatGPT で記事を量産できる人間が全国に数万人いる。この領域はレッドオーシャンだ。

領域② 業務自動化スクリプト（推定 800〜1,200 件）

Excel マクロ・Google Apps Script・Python の小規模ツール。売上集計・メール送信・データ変換・レポート作成の自動化。単価は 1 件 10,000〜60,000 円。競合密度は低い。エンジニアが参入してこない理由は「単価が中途半端で割に合わない」から。でも非エンジニアにとっては時給換算で圧倒的に高い領域。

領域③ Web アプリ UI／LP 制作（推定 1,500〜2,000 件）

ランディングページ制作・管理画面 UI・予約システム・フォーム作成。単価は 1 件 30,000〜100,000 円。Claude Code との相性が非常に良い領域。非エンジニアでも Claude Code に指示するだけで形にできる。

領域④ ChatGPT プロンプト作成・カスタム GPTs（推定 400〜600 件）

企業向けの AI プロンプト設計代行。単価は 1 件 5,000〜30,000 円。増加トレンド。プロンプト設計はコード知識不要だが、ヒアリング力と業務理解力が必要。

領域⑤ データ分析・リサーチ代行（推定 300〜500 件）

市場調査・競合分析・業界レポート作成。単価は 1 件 10,000〜50,000 円。AI を使った情報整理の案件が増えている。

全部合わせて 5,832 件。内訳が偏っている。領域①だけで半分超。残り 2,800 件が②〜⑤に散らばっている。

つまり、検索結果の上位を「AIライター」が埋め尽くしているのは、案件全体の半分以上が①領域だからだ。残り半分近くを見つけるには、検索キーワードを変えるしかない。

非エンジニアが選ぶべき 2 領域

5 領域のうち、非エンジニアに向いているのは業務自動化と Web アプリ UI の 2 つに絞られる。残り 3 領域はやめておいたほうがいい。

領域① AI ライティングをやめるべき理由

単価が崩壊している。AI 生成物がバレる率も高い。継続案件化しにくい（記事 1 本で終わる）。参入障壁がゼロなので競合が常に流入する。文字単価 0.3 円では、6 桁の収益に到達するのに膨大な文字数が必要になる。時給換算で現実的じゃない。

領域④ プロンプト作成をあとまわしにする理由

企業向けのヒアリング力が最優先で求められる領域。業務理解・要件定義・納品後のサポートまでセット。非エンジニアの初心者がいきなり受けると、要件が膨らんで納品が終わらないパターンに陥る。業務自動化で実績を作ってから入るのが現実的。

領域⑤ データ分析をあとまわしにする理由

統計知識・業界知識・レポート作成力が必要。Claude を使っても、本質的な分析力は人間側に求められる。初心者のうちは、自分の専門分野と重なる案件だけ受けるのが無難。

残るのが②業務自動化と③ Web アプリ UI。この 2 つに絞る。

領域② 業務自動化を選ぶ 4 つの理由

理由 1 単価が高い。1 件 10,000 円を割る案件はほぼない。領域①の文字単価換算で 30,000〜60,000 字に相当する。

理由 2 継続案件化しやすい。自動化スクリプトは「改修」「追加機能」で何度も仕事が来る。一度納品して動くようになると、クライアント側が手放せなくなる。

理由 3 競合密度が低い。エンジニアは「割に合わない」と避ける。非エンジニアは「自分にはできない」と思い込んでいる。結果として、この領域は常に人不足。

理由 4 Claude Code との相性が最高。Google Apps Script や Python のシンプルなスクリプトは、Claude Code に日本語で伝えるだけで生成できる。

領域③ Web アプリ UI を選ぶ 3 つの理由

理由 1 単価がさらに高い。1 件 30,000〜100,000 円。月 2 件で 6 万〜20 万円になる。

理由 2 制作経験がなくても Claude Code で形にできる。HTML / CSS / JavaScript のシンプルな構成なら、指示書をそのまま Claude Code に投げると動くものが返ってくる。

理由 3 ポートフォリオが積み上がる。制作物が残るので、次の案件獲得で実績として提示しやすい。

案件選定の基準 7 項目

案件タイトルと本文の 3 行で、受けるべきか判断できる基準がある。以下の 7 項目を順番にチェックするだけで、応募の無駄打ちがほぼ消える。

① 予算が明記されているか。「相談」だけの案件は避ける。値切り前提になりがち。

② 予算が 1 万円以上あるか。1 万円未満の業務自動化案件は要件が不明瞭なことが多い。

③ 納期が 7 日以上あるか。納期 2 日の案件は要件変更に対応できない。

④ 募集文が 200 字以上あるか。短すぎる募集文はクライアントが要件を整理できていない。

⑤ 「継続依頼の可能性あり」「改修できる人募集」「長期的に依頼したい」等の文言があるか。継続率が上がる。

⑥ クライアントの評価が 4.5 以上か。評価 4 未満のクライアントは払いが悪い・要件変更が多い傾向。

⑦ AI 使用の可否が明示されているか。「AI 可」「ChatGPT 可」の明示があれば迷わず使える。「使用不可」の案件は避ける。

7 項目のうち 5 項目以上クリアしたら応募する。4 項目以下ならスキップする。

ケース 1 Excel 業務自動化（予算 ¥18,000・納期 5 日）

Day 1 案件発見。「毎週月曜に売上データを集計して、部門別レポートをメール送信する業務を自動化したい」という案件。予算 ¥18,000、納期 5 日。クライアント評価 4.8。

Day 1 続き。プロンプト 1 で案件分析。真の目的は「月曜の朝 2 時間の手作業を消したい」。明記されていない要件として「土日に Excel が更新されている場合、どうするか」「エラー時の通知先」の 2 つを発見。

Day 1 続き。プロンプト 3 のテンプレ A（気づき添え型）で応募文を作成。「土日にデータ更新がある場合のハンドリング」を提案として添える。想定工数 5 時間、予算 ¥18,000 ちょうどで提案。

Day 2 クライアントから返信。「土日のハンドリングは考えていなかった。追加してほしい」。応募 5 名中で自分が選ばれた。気づき添え型の提案が評価ポイントになった。

Day 2 続き。プロンプト 2 で要件確認メッセージ送信。追加要件 3 項目を整理し、1 時間で返信が来る。

Day 3 プロンプト 5 で Claude Code に Google Apps Script のコード生成を指示。30 分で動くコードが出る。ローカルで動作確認、月曜朝のタスクトリガー設定まで完了。

Day 4 プロンプト 6 で動作確認の観点を整理。3 パターンのテストケースを手動で流す。エラーハンドリングに 1 箇所不備を発見、Claude Code に修正指示で 10 分で解消。

Day 5 プロンプト 7 で納品メッセージ作成。動作確認手順 5 ステップ・想定質問 4 項目を先回りで記載。クライアントから「質問が全部先回りで答えられていて助かった」と評価 5。

総作業時間 6 時間 30 分。時給換算 ¥2,769。

継続案件化のコツ 5 項目

1 件納品で終わらせず、継続依頼に化けさせる納品時の工夫。

① 納品物に「運用マニュアル」を同梱する。クライアントが 1 人で運用できるようにする。「困ったらまた相談したい」と思わせる。

② 納品メッセージに「想定される質問と回答」を 3〜5 項目先回りで書く。クライアントが質問する前に答えが用意されていると信頼度が跳ね上がる。

③ 納品時に「関連する業務で自動化できそうな箇所」を 1〜2 個だけ提案する。売り込みにならない程度の軽い提案が継続依頼に化ける。

④ 納品後 1 ヶ月、3 ヶ月のタイミングでプロンプト 8 で声かけする。「その後、順調に稼働されていますか」の一言だけ。押し売りではなく、気遣いの文脈。

⑤ クライアントからの質問には 24 時間以内に返信する。納品後のアフターフォロー期間は無償で対応する範囲を明示する（例 納品後 2 週間は無償修正対応）。

この 5 項目を守るだけで、継続率が体感で 6 割超に達する。

つまずき 3 パターンと回避策

非エンジニアが最初の 1 ヶ月で必ず踏むつまずき。事前に知っておけば回避できる。

パターン 1 要件が膨らんで納期遅延

クライアントから「これもできる？」「ついでにこれも」と追加要求が来る。断れずに引き受けて、工数が 2 倍に膨れて赤字になる。

回避策。プロンプト 9（単価交渉プロンプト）を使って、追加要件が来たら必ず見積もり再提示する。「今回の予算内では対応が難しいので、追加分は別途お見積もりします」と明言する。最初の契約時に「スコープ外の作業は別途相談」の一文を添える。

パターン 2 Claude Code の出力を信じて納品してバグ発覚

Claude Code が書いたコードを動作確認せずに納品する。クライアントが動かしてエラーが出て、評価が下がる。

回避策。プロンプト 6（動作確認プロンプト）を必ず使う。正常系 3 パターン・異常系 3 パターンを手動で流してから納品する。30 分の動作確認時間を工数に含める。

パターン 3 クライアントの要件変更に対応しきれず納期遅延

制作中にクライアントから仕様変更が来る。対応していると納期を超える。

回避策。契約時に「仕様変更は工程の 50% 完了までに確定」「それ以降の変更は追加見積もり」と明記する。プロンプト 2（要件整理プロンプト）を使って、早期に要件を固めておく。

他ジャンル応用のヒント

本記事は業務自動化と Web アプリ UI の 2 領域に絞ったが、ここで紹介した手法は他領域にも応用できる。

領域④プロンプト作成に応用する場合、プロンプト 2（要件整理）の比重が上がる。業務理解のヒアリングが最重要工程になる。実績を積んでから参入するのが無難。

領域⑤データ分析に応用する場合、プロンプト 1（案件分析）で「何を分析すれば意思決定に繋がるか」まで踏み込んで整理する。単なるデータ加工ではなく、提案つき分析にすると単価が上がる。

本記事のテンプレ 5 パターン・プロンプト 10 本は、ジャンルを問わず使える構造にしてある。案件の核心が変わっても、骨格は流用できる。
