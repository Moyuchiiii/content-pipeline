SEO比較記事ライターの単価、知ってますか？

あなたがSEO記事ライター案件をちらっと見たことあるなら、文字単価の数字は知ってると思う。

調べ直してみた。クラウドワークスのオールジャンル平均は1文字1円。初心者は0.3〜0.5円。3年以上の経験者でやっと3円というのが現役ライターのまとめだった。

つまり、3,000字の比較記事を書いて報酬3,000円。これが標準ライン。

1記事にかかる時間はどうか。ブロガー・ライター100人のアンケートによると、3,000字の記事作成で89%が1時間以上かかってる。5時間以上が14人いた。

比較記事の場合は、調査と情報整理に追加で時間がかかる。半日〜数日が標準だと検索結果は言ってた。

これ、時給換算するとどうなる？

3,000円 ÷ 4時間 = 時給750円。

大学のバイトと変わらない。AIを使わない限り、SEO比較記事ライター案件は「副業として成立しないジャンル」だった。

7エージェント定義ファイル、全部見せる

このパイプラインの中核は、Claude Codeのsubagents機能で動く7体のエージェント。1体ずつ役割と設計を見ていく。

researcher リサーチ担当

役割は、競合上位記事の分析・関連キーワード収集・商品スペック情報の取得。キーワードを受け取ったら、Web検索で上位10記事を確認し、各記事の見出し構成・引用元・取り上げ商品を抽出する。

出力は構造化されたリサーチレポートとして、次の構成担当に渡される。タイトル候補、競合の弱点、AIO引用されやすそうな箇所も同時に出す。

定義ファイルは .claude/agents/researcher.md。プロンプトは「あなたはSEO記事のリサーチ担当」という役割定義から始まって、出力フォーマット・確認すべき項目・取得するデータの型を明示してる。書き換えれば、自分のサイト方針に合わせた調査範囲に変えられる。

structure-designer 構成担当

役割は、見出し構成設計・AIOターゲット設計・吹き出し配置計画・パーマリンク案の作成。リサーチ結果を受けて、H1からH3までのツリー構造を組み立てる。

同時に、検索意図をKnow / Do / Buy / Go型に分類し、それぞれに合ったH2の切り口を選定する。AIO引用を狙うキーワードと、それに対応するスニペット候補文40〜80文字も事前設計する。

構成案が完成したら、ユーザーに提示して承認を待つ。ここがパイプライン唯一の人間判断ポイント。

structure-checker 構成チェック担当

役割は、構成担当が出した構成案をSEO / UX / AIO観点でレビューすること。「H3の粒度が粗すぎないか」「AIOターゲットが少なすぎないか」「比較表の列が読者の疑問に答えているか」を確認する。

FAILがあれば構成担当に差し戻して修正させる。PASSしたら執筆担当に渡す。

writer 執筆担当

役割は、承認済み構成と商品情報を受けて、セクションごとに本文を執筆すること。出力は1つのファイルにまとめられ、次の校正担当に渡される。

本文には、キャラクター吹き出し、ビジュアルボックス8種、FAQアコーディオン、ランキングカード、個別レビュー統合カードが自動挿入される。各装飾の使い分けルールは、後述の「8種ビジュアルボックスの使い分け」で詳しく扱う。

文体は「です・ます調」で統一、結論ファースト、1文60文字以内が原則。各H3直下の冒頭はこの構造で出力される。

光回線を選ぶ際は、まず月額料金を確認しましょう。相場は3,000〜5,500円程度で、キャンペーン適用後の実質料金で比較するのがポイントです。

結論先行・具体的な数値・読者への語りかけが揃った状態で、各セクションが書き起こされる。

reviewer 校正担当

役割は、執筆担当が書いた本文を全文チェックすること。誤字脱字、文体の統一、結論ファースト構造の徹底、吹き出しのペア確認（キャラA→キャラB の順）、ビジュアルボックスの使い分けを確認する。

修正が多い場合は執筆担当に差し戻す。少ない場合は自分で修正してからAIO最適化担当に渡す。

aio-optimizer AIO最適化担当

役割は、JSON-LD生成とAI引用最適化。4つのスキーマ（FAQPage / ItemList / HowTo / BreadcrumbList）を本文末尾に挿入する。

同時に、AIOスニペット候補一覧を最終出力時に提示する。各H2の冒頭に配置されたスニペット候補文と、対応するキーワードがマッピングされたリスト。

quality-gate 品質ゲート担当

役割は、最終HTMLのテンプレート準拠・プレースホルダー・構造チェック。「ランキングカードが正しく使われているか」「個別レビュー統合カードで裸のH3が出ていないか」「FAQアコーディオンがdlタグで書かれていないか」を機械的に検証する。

FAILが1件でもあれば、該当エージェントに差し戻して修正させる。最大2回差し戻しても直らない場合はユーザーに報告して判断を仰ぐ。

PASSしたら、ディレクターが最終HTMLをoutputフォルダに保存し、レポートをユーザーに提示する。

AI Overviewに引用される構造化マークアップ

2026年現在、Google AI Overviewに引用されるかどうかは、検索流入の死活問題になってる。このパイプラインは、AIO引用に必要な4種類のJSON-LDと、引用されやすい記事構造を全自動で生成する。

FAQPageスキーマ

FAQセクションのQ&Aをすべて構造化する。質問文はH3テキストと完全一致、回答テキストはHTMLタグなしのプレーンテキスト。AIが直接引用しやすい形に整える。

実際の出力はこの形になる。

{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "光回線とは何ですか？",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "光回線とは、光ファイバーケーブルを使ったインターネット接続サービスです。最大1〜10Gbpsの高速通信が可能で、安定性に優れています。"
      }
    }
  ]
}

FAQ 1問あたりこのJSONブロックが生成され、5問以上が自動的に配置される。

ItemListスキーマ

ランキング表の全商品を構造化する。position・name・urlのセットで、1から連番で記述。商品リスト全体がAIに「ランキングである」と認識される設計。

HowToスキーマ

選び方セクションを手順として構造化する。各比較軸をHowToStepとして記述し、name（H3テキスト）とtext（説明文の要約）を含める。

BreadcrumbListスキーマ

パンくずリストを構造化する。URLはプレースホルダーで出力されるため、サイトの実URLに手動で差し替える運用。

結論ファーストの徹底

AIOは、ページ内の「直接的な回答」を引用する傾向がある。各セクションの冒頭に必ず結論・答えを置くことで、引用されやすくなる。

H2直下の最初の段落
そのセクションの結論を1〜2文で書く

H3直下の最初の段落
その比較軸での結論を1文で書く

FAQの各回答
1文目が直接的な答え、2文目以降に補足を書く

このルールは、執筆担当エージェントのプロンプトに明示されてる。守られないと、構成チェック担当か校正担当が差し戻す。

定義文の配置と「とは」FAQ

記事の序盤に「ジャンルとは、定義文1〜2文、プレーンな説明」を必ず配置する。これはAIOが「定義クエリ」に対して引用しやすい構造。

同時に、FAQには「ジャンルとは」「ジャンルの選び方」「ジャンルの違い」「ジャンルはいくら」「ジャンルのデメリット」など、検索クエリの種類を混在させる。

1回答100〜200文字程度に抑えるのもポイント。短すぎても長すぎてもAIOに引用されにくくなる。

比較表の要件

スペック比較や料金比較は、必ずtableタグで構造化する。divで組んだ表はAIに認識されないため禁止。

theadとtbodyを分け、列ヘッダーには th scope="col"、行ヘッダー（商品名列）には th scope="row" を使う。captionまたはaria-labelでテーブルの説明を付けると、AIOがテーブルの主題を理解しやすくなる。

マイベスト風のレイアウトを実現するため、8種類のビジュアルボックスを使い分ける。単純な箇条書きだけでは視認性が低く、滞在時間にも影響する。8種類の使い分けルールを明確にした。

品質ゲートが何をチェックするか

品質ゲート担当は、このパイプラインの最後の砦。最終HTMLをチェックして、PASS / FAILを判定する。FAILがあれば、該当エージェントに差し戻して修正させる。

JSON-LD 4種が全て生成されているか
FAQPage / ItemList / HowTo / BreadcrumbList

キャラクター吹き出しが必ずペアで挿入されているか
キャラA → キャラB の順

プレースホルダーが残っていないか
残っていればWARNとして報告

差し戻しフロー

FAILが出た場合、品質ゲート担当が該当エージェントを名指しで差し戻す。例えば「JSON-LDのHowToが抜けている」場合はAIO最適化担当に、「ランキングカードではなく旧tableが使われている」場合は執筆担当に、それぞれ修正依頼が送られる。

最大2回差し戻しても直らない場合は、ディレクターを通じてユーザーに報告し、手動修正の判断を仰ぐ。これは無限ループ防止のセーフティ。

つまずき5ポイント

あなたが最初に踏みそうな落とし穴を、先に書いておく。わたしが全部踏んだやつ。

ポイント1 構成案を承認せずに放置で停止する

構成担当が構成案を提示した後、ユーザーが「OK」と返さないとパイプラインが進まない。深夜や移動中に起動すると、構成案承認のタイミングで停止することがある。

気づかずに1時間放置したことがある。再起動すれば続きから動くけど、ターミナルを閉じてしまうとセッションが消える場合があるから注意。

回避策は、パイプラインを起動するときは、構成案の承認まで対応できる5〜10分の余裕を確保してから始めること。

ポイント2 商品ロゴ画像のプレースホルダーを差し替え忘れる

商品ロゴ画像は著作権の観点から自動取得されない。プレースホルダー「[ロゴ画像URL]」のまま出力される。差し替え忘れると、本番記事に「[ロゴ画像URL]」というテキストがそのまま表示される。

回避策は、出力後の確認チェックリストに「プレースホルダー全件差し替え」を必ず入れること。Ctrl+Fでファイル内検索すると漏れがない。

ポイント3 料金情報の最終目視確認を飛ばす

料金・スペック情報はWeb検索ベースのため、最新情報と差異がある場合がある。検索した時点では正しくても、翌月にキャンペーン期間が終わって料金が変わる可能性がある。

回避策は、公開前に必ず各商品の公式サイトで最新料金を確認すること。チェックは数分で終わるけど、これを飛ばすと記事の信頼性が一気に落ちる。

ポイント4 ジャンルキーワードを抽象的に入れすぎる

「副業 おすすめ」のような広すぎるキーワードを入れると、リサーチ範囲が広すぎて出力が散漫になる。AIO引用も狙いにくくなる。

回避策は、「光回線 おすすめ 一人暮らし」「ウォーターサーバー 比較 ペットボトル不要」のように、対象とターゲットを絞ったキーワードを入れること。具体的なほど質が上がる。

ポイント5 1記事のAPIトークン消費を見積もらない

7エージェント並列パイプラインは、Claude APIトークンを通常の対話より多く消費する。Pro $20の枠を超えるとAPI直接課金が走るため、想定外の請求が発生する場合がある。

回避策は、最初の数本を回して1本あたりの消費量を把握すること。それを月初に掛けて「今月の予算」を見積もる。Pro枠で足りない見込みなら、API直接課金の上限を事前に設定するのが安全。

キャラクター吹き出し・テンプレCSSのカスタマイズ

このパイプラインには、汎用キャラ「キャラA 質問役・生徒役」と「キャラB 回答役・先生役」の吹き出し機能が同梱されてる。各サイトのブランドキャラに置き換えると、サイト全体の統一感が出る。

キャラ画像URLの差し替え

seo-writing.md と html-output.md と writer.md の3箇所に、キャラ画像URLのプレースホルダーがある。「キャラA_アイコンURL」「キャラB_アイコンURL」を、自社サイトにアップロード済みの実画像URLに置き換える。

推奨画像サイズは56×56ピクセルの円形で、jpgまたはpng形式。背景透過pngを使うと吹き出しになじむ。

キャラ名・口調のカスタマイズ

キャラ名（キャラA / キャラB）は、seo-writing.md の「キャラクター設定」テーブルで変更できる。自社のキャラ名（例「ゆかさん」「ねこ博士」）に書き換える。

口調も、seo-writing.md の「口調」列で調整できる。質問役は丁寧語、回答役はタメ口を基本としてるけど、サイトのブランドトーンに合わせて変更してOK。

ブランドカラー対応

templates/article-skeleton.html と templates/ranking-table.html の冒頭に、CSS変数（root）が定義されてる。

:root {
  --color-primary: #1a56db;  /* メインカラー */
  --color-accent: #e67e22;   /* アクセントカラー */
  --color-success: #27ae60;  /* CTAボタン */
}

color-primary（メインカラー）・color-accent（アクセントカラー）・color-success（CTAボタン色）の3変数を書き換えると、サイト全体のカラーテーマが一気に変わる。

例えば、color-primaryを青系から緑系に変更すると、ランキングカードのバッジ色・ボタン色・見出し帯色がすべて連動して変わる。ジャンル別に色を分けてサイトを複数運営する、みたいな使い方もできる。

FAQ

Claude Codeを入れたことがなくても再現できる？

記事の前半にClaude Codeの最小セットアップ手順を書いてる。Claudeのブラウザ版を触ったことがあれば理解できる前提で書いてるけど、Claude Code自体のインストールは公式ドキュメント docs.anthropic.com を参照してほしい。インストール自体は10分以内で終わる。

Claude Pro月額$20の課金は必要？

Pro推奨。1記事の生成にClaude APIトークンを通常の対話より多く消費するため、無料版だと途中で枠が尽きる場合がある。Pro $20の枠で動かす場合、使用量によって変動するため、最初の数本を回して消費量を把握してから月の生成計画を立てるのが現実的。

1記事あたりのAPIトークン消費はどのくらい？

記事の文字数、リサーチの深さ、差し戻しの回数によって変動する。使用量に個人差があるため、最初の数本を回して1本あたりの消費量を把握し、月初に「今月何本生成するか」を見積もるのが現実的。

WordPress以外のブログでも使える？

使える。出力はHTML本文のみなので、note・はてなブログ・ライブドアブログ・自作CMSなど、HTML直貼り対応のあるプラットフォームならどこでも動く。出力形式はWordPress直貼り形式で、headタグもbodyタグも含まれない。

絶対にAI Overviewに引用される？

そういう保証はできない。AI Overviewの引用ロジックはGoogle側で常に変動してる。このパイプラインは「引用されやすい構造」を生成するけど、引用そのものを保証する商品ではない。ただし、構造化マークアップ・結論ファースト・FAQ 5問以上などの引用最適化要件は全て満たした状態で出力される。

SEOアフィリエイト未経験でも使える？

使えるけど、購入前に1本は手書きで試してから読んだほうがいい。下地となる「読者像の理解」「ジャンルの相場感」がないと、AIが出してきた内容を評価できない。1本書いてみて「このジャンル続けたい」と思ったら、ツールで量産に切り替えるのが現実的な順番。
