FAQ

Claude Code を入れたことがなくても再現できる？

記事の前半に Claude Code の最小セットアップ手順を書いています。Claude のブラウザ版を触ったことがあれば理解できる前提で書いていますが、Claude Code 自体のインストールは公式ドキュメント docs.anthropic.com を参照してください。

Claude Pro 月額 $20 の課金は必要？

Pro 推奨です。1 記事の生成に Claude API トークンを通常の対話より多く消費するため、無料版だと途中で枠が尽きる場合があります。Pro $20 の枠で動かす場合、使用量によって変動するため、最初の数本を回して消費量を把握してから月の生成計画を立てるのが現実的です。

1 記事あたりの API トークン消費はどのくらい？

記事の文字数、リサーチの深さ、差し戻しの回数によって変動します。使用量に個人差があるため、最初の数本を回して 1 本あたりの消費量を把握し、月初に「今月何本生成するか」を見積もるのが現実的です。本ツールの第 5 章で、消費量の確認方法も合わせて解説しています。

WordPress 以外のブログでも使える？

はい、出力は HTML 本文のみなので、note・はてなブログ・ライブドアブログ・自作 CMS など、HTML 直貼り対応のあるプラットフォームならどこでも使えます。出力形式は WordPress 直貼り形式で、head タグも body タグも含まれません。

絶対に AI Overview に引用される？

そういう保証はできません。AI Overview の引用ロジックは Google 側で常に変動しています。このパイプラインは「引用されやすい構造」を生成しますが、引用そのものを保証する商品ではありません。ただし、構造化マークアップ・結論ファースト・FAQ 5問以上などの引用最適化要件は全て満たした状態で出力されます。

7 つの工程の流れ

このパイプラインは、Claude Code 上で 7 体のエージェントが連携して動きます。ディレクター役のメインセッションが、各エージェントに指示を出し、最終的に WordPress 直貼り HTML を統合します。

順番に見ていくと:

工程 1 リサーチ担当が競合上位記事を分析し、関連 KW・商品情報を収集

工程 2 構成担当が見出し構成・AIO ターゲット設計・吹き出し配置計画・パーマリンク案を設計

工程 3 構成チェック担当が SEO・UX・AIO 観点でレビュー

工程 4 執筆担当がセクションごとに本文を執筆 吹き出し・ビジュアルボックス・FAQ含む

工程 5 校正担当が全文をチェック・修正

工程 6 AIO 最適化担当が JSON-LD を生成し、AI 引用最適化を行う

工程 7 品質ゲート担当がテンプレート準拠・プレースホルダー・構造をチェック PASS 後のみ保存

これら 7 工程を、ディレクター メインセッションが順次起動して回します。

どの工程から手をつけるべきか

結論から書くと、工程は「順番に動く」だけで、独立に動かす運用はしません。キーワードを入力すると、ディレクターが全 7 工程を自動的に順次起動します。

あなたが手を入れるのは、工程 2 と工程 3 の間にある「構成案の承認」だけです。構成案が提示されたら、見出しや AIO ターゲットを確認して「OK」と返すか、修正指示を出します。

それ以降は、エージェント間でデータが受け渡されて、最終 HTML が出力されるまでノータッチで進みます。

「キーワード入れるだけ」の判断ロジック

このパイプラインは、ジャンルを問わず動作します。ジャンルに応じて H2 の切り口が自動的に最適化される設計になっています。

例えば「光回線 おすすめ ランキング」と入れると通信系ジャンルの定番構成、つまり料金・速度・キャンペーンの軸で組まれます。「ウォーターサーバー 比較」と入れると、サーバー本体・水代・配送・電気代の比較軸が組まれます。

判断ロジックは、構成担当エージェントの内部に組み込まれています。検索意図を Know 型・Do 型・Buy 型・Go 型に自動分類して、ジャンルに最適な構成テンプレを選びます。

researcher リサーチ担当

役割は、競合上位記事の分析・関連キーワード収集・商品スペック情報の取得です。キーワードを受け取ったら、Web 検索で上位 10 記事を確認し、各記事の見出し構成・引用元・取り上げ商品を抽出します。

出力は構造化されたリサーチレポートとして、次の構成担当に渡されます。タイトル候補、競合の弱点、AIO 引用されやすそうな箇所も同時に出します。

structure-designer 構成担当

役割は、見出し構成設計・AIO ターゲット設計・吹き出し配置計画・パーマリンク案の作成です。リサーチ結果を受けて、H1 から H3 までのツリー構造を組み立てます。

構成案が完成したら、ユーザーに提示して承認を待ちます。ここがパイプライン唯一の人間判断ポイントです。

structure-checker 構成チェック担当

役割は、構成担当が出した構成案を SEO / UX / AIO 観点でレビューすることです。「H3 の粒度が粗すぎないか」「AIO ターゲットが少なすぎないか」「比較表の列が読者の疑問に答えているか」を確認します。

FAIL があれば構成担当に差し戻して修正させます。PASS したら執筆担当に渡します。

writer 執筆担当

役割は、承認済み構成と商品情報を受けて、セクションごとに本文を執筆することです。出力は 1 つのファイルにまとめられ、次の校正担当に渡されます。

本文には、キャラクター吹き出し、ビジュアルボックス 8 種、FAQ アコーディオン、ランキングカード v3、個別レビュー統合カード v4 が自動挿入されます。各装飾の使い分けルールは、後述の第 3 章で詳しく扱います。

文体は「です・ます調」で統一、結論ファースト、1 文 60 文字以内が原則です。

例えば、各 H3 直下の冒頭はこの構造で出力されます。

光回線を選ぶ際は、まず月額料金を確認しましょう。相場は 3,000〜5,500 円程度で、キャンペーン適用後の実質料金で比較するのがポイントです。

結論先行・具体的な数値・読者への語りかけが揃った状態で、各セクションが書き起こされます。

reviewer 校正担当

役割は、執筆担当が書いた本文を全文チェックすることです。誤字脱字、文体の統一、結論ファースト構造の徹底、吹き出しのペア確認 キャラA → キャラB の順、ビジュアルボックスの使い分けを確認します。

修正が多い場合は執筆担当に差し戻します。少ない場合は自分で修正してから AIO 最適化担当に渡します。

aio-optimizer AIO 最適化担当

役割は、JSON-LD 生成と AI 引用最適化です。4 つのスキーマ FAQPage / ItemList / HowTo / BreadcrumbList を本文末尾に挿入します。

同時に、AIO スニペット候補一覧を最終出力時に提示します。各 H2 の冒頭に配置されたスニペット候補文と、対応するキーワードがマッピングされたリストです。

quality-gate 品質ゲート担当

役割は、最終 HTML のテンプレート準拠・プレースホルダー・構造チェックです。「ランキングカード v3 が正しく使われているか」「個別レビュー統合カード v4 で裸の H3 が出ていないか」「FAQ アコーディオンが dl タグで書かれていないか」を機械的に検証します。

FAIL が 1 件でもあれば、該当エージェントに差し戻して修正させます。最大 2 回差し戻しても直らない場合はユーザーに報告して判断を仰ぎます。

PASS したら、ディレクターが最終 HTML を output フォルダに保存し、レポートをユーザーに提示します。

第 2 章 AI Overview 引用される構造化マークアップ全部

2026 年現在、Google AI Overview に引用されるかどうかは、検索流入の死活問題です。このパイプラインは、AIO 引用に必要な 4 種類の JSON-LD と、引用されやすい記事構造を全自動で生成します。

4 つの JSON-LD スキーマ

生成される JSON-LD は次の 4 種類です。

FAQPage スキーマ — FAQ セクションの Q&A をすべて構造化します。質問文は H3 テキストと完全一致、回答テキストは HTML タグなしのプレーンテキスト。AI が直接引用しやすい形に整えます。

実際の出力はこの形になります:

{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "光回線とは何ですか？",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "光回線とは、光ファイバーケーブルを使ったインターネット接続サービスです。最大 1〜10Gbps の高速通信が可能で、安定性に優れています。"
      }
    }
  ]
}

FAQ 1 問あたりこの JSON ブロックが生成され、5 問以上が自動的に配置されます。

ItemList スキーマ — ランキング表の全商品を構造化します。position・name・url のセットで、1 から連番で記述。商品リスト全体が AI に「ランキングである」と認識される設計です。

HowTo スキーマ — 選び方セクションを手順として構造化します。各比較軸を HowToStep として記述し、name H3 テキスト と text 説明文の要約 を含めます。

BreadcrumbList スキーマ — パンくずリストを構造化します。URL はプレースホルダーで出力されるため、サイトの実 URL に手動で差し替える運用です。

結論ファーストの徹底

AIO は、ページ内の「直接的な回答」を引用する傾向があります。各セクションの冒頭に必ず結論・答えを置くことで、引用されやすくなります。

H2 直下の最初の段落 そのセクションの結論を 1〜2 文で書きます。

H3 直下の最初の段落 その比較軸での結論を 1 文で書きます。

FAQ の各回答 1 文目が直接的な答え、2 文目以降に補足を書きます。

このルールは、執筆担当エージェントのプロンプトに明示されています。守られないと、構成チェック担当か校正担当が差し戻します。

定義文の配置と「とは」FAQ

記事の序盤に「ジャンルとは、定義文 1〜2 文、プレーンな説明」を必ず配置します。これは AIO が「定義クエリ」に対して引用しやすい構造です。

同時に、FAQ には「ジャンル とは」「ジャンル の選び方」「ジャンル の違い」「ジャンル はいくら」「ジャンル のデメリット」など、検索クエリの種類を混在させます。

1 回答 100〜200 文字程度に抑えるのもポイントです。短すぎても長すぎても AIO に引用されにくくなります。

比較表の要件

スペック比較や料金比較は、必ず table タグで構造化します。div で組んだ表は AI に認識されないため禁止です。

thead と tbody を分け、列ヘッダーには th scope="col"、行ヘッダー 商品名列には th scope="row" を使います。caption または aria-label でテーブルの説明を付けると、AIO がテーブルの主題を理解しやすくなります。

特徴まとめカード

サービス・商品の基本情報整理に使います。各 H3 の冒頭に配置し、表形式で「項目名 / 内容」を並べます。読者が「結局なんのサービス」と確認したいときの参照ポイントになります。

チェックリストボックス

ポジティブな要点をグリーンで整理するボックスです。Tips・ポイント・コツの提示に使います。番号なしで、チェックマーク (✓) 付きのリスト構造。

番号付きチェックリストボックス

警告ボックス

セキュリティ注意・禁止事項・リスクの明示に使います。レッド系で、目を引く色合い。本文の流れを一瞬止めて、読者の意識を引き戻す効果があります。

つまずき 5 ポイント

導入時に踏みやすい 5 つの落とし穴と、回避策をまとめます。

ポイント 1 構成案を承認せずに放置で停止する

構成担当が構成案を提示した後、ユーザーが「OK」と返さないとパイプラインが進みません。深夜や移動中に起動すると、構成案承認のタイミングで停止することがあります。

回避策 パイプラインを起動するときは、構成案の承認まで対応できる 5〜10 分の余裕を確保してから始めます。

ポイント 2 商品ロゴ画像のプレースホルダーを差し替え忘れる

商品ロゴ画像は著作権の観点から自動取得されず、プレースホルダー「ロゴ画像 URL」のまま出力されます。差し替え忘れると、本番記事に「[ロゴ画像URL]」というテキストがそのまま表示されます。

回避策 出力後の確認チェックリストに「プレースホルダー全件差し替え」を必ず入れます。Ctrl+F でファイル内検索すると漏れがありません。

ポイント 3 料金情報の最終目視確認を飛ばす

料金・スペック情報は Web 検索ベースのため、最新情報と差異がある場合があります。検索した時点では正しくても、翌月にキャンペーン期間が終わって料金が変わる可能性があります。

回避策 公開前に必ず各商品の公式サイトで最新料金を確認します。チェックは数分で終わりますが、これを飛ばすと記事の信頼性が一気に落ちます。

ポイント 4 ジャンルキーワードを抽象的に入れすぎる

「副業 おすすめ」のような広すぎるキーワードを入れると、リサーチ範囲が広すぎて出力が散漫になります。AIO 引用も狙いにくくなります。

回避策 「光回線 おすすめ 一人暮らし」「ウォーターサーバー 比較 ペットボトル不要」のように、対象とターゲットを絞ったキーワードを入れます。具体的なほど質が上がります。

ポイント 5 1 記事の API トークン消費を見積もらない

7 エージェント並列パイプラインは、Claude API トークンを通常の対話より多く消費します。Pro $20 の枠を超えると API 直接課金が走るため、想定外の請求が発生する場合があります。

回避策 最初の数本を回して、1 本あたりの消費量を把握します。それを月初に掛けて「今月の予算」を見積もります。Pro 枠で足りない見込みなら、API 直接課金の上限を事前に設定するのが安全です。

1. まず「キーワード 1 つだけ」で 1 記事生成してみる。
完璧なジャンル選定をしようとすると動けなくなる。テスト用に 1 つ動かしてみると、構成案の承認ポイント・出力の質・WordPress 貼り付け感覚が一気にわかる。最初の 1 本は「実験」と割り切る。

2. 1 記事あたりの API トークン消費を、月初に見積もる。
Pro $20 の枠で月何本まで生成できるかは、最初の 3 本を回せば見えてくる。それを記録しておくと、月の生成計画が立てやすい。

3. ジャンル別カスタマイズを 1 つだけ深掘りする。
全ジャンルに手を広げると、どのジャンルも中途半端になる。最初の 3 ヶ月は 1 ジャンルだけ深掘りして、サイトに 10〜20 本を蓄積する。AIO 引用は記事数とサイト全体の信頼性で決まる。
